# Счётчик посещений AniCast

## Назначение

Счётчик показывает общее количество посещений и количество за текущие сутки
в Django Admin («Посещения по дням», только чтение). Эти же агрегаты доступны
операторам как Prometheus gauge `anicast_site_visits{period="today|total"}`.
Публичный footer счётчик не показывает (намеренно: vanity-метрика не стоит
места в подвале).

## Что считается посещением

- Одно посещение на браузер за календарные сутки UTC.
- Счётчик вызывается клиентом один раз после загрузки интерфейса через
  `POST /api/v1/analytics/visit/` (см. `frontend/components/visit-tracker.tsx`).
- Повторные страницы и обновления в том же браузере за сутки не увеличивают показатель.
- Известные поисковые роботы, headless-проверки, curl/wget, пустой user-agent
  и monitoring user-agent не учитываются.

Это продуктовый индикатор активности, а не строгая метрика уникальных людей. Очистка cookies или разные браузеры могут дать несколько посещений; одновременно открытые первые вкладки в редком случае также могут конкурировать.

## Приватность

Backend хранит только дату UTC, число посещений и служебные timestamps. IP-адрес, user-agent, аккаунт и browser fingerprint не сохраняются. Для дедупликации используется подписанная first-party cookie `anicast_visit_day` (`salt=anicast.visit-day.v1`) с флагами `HttpOnly`, `Secure` в production и `SameSite=Lax`; срок жизни — двое суток. Троттлится только ветка подсчёта (`visit=600/hour` на адрес): повторные заходы с cookie бюджет не тратят, исчерпание лишь недоучитывает vanity-метрику и никогда не роняет загрузку. Сводка `total/today` кэшируется 60с. Сутки — `TIME_ZONE` из env (по умолчанию UTC).

Endpoint защищён CSRF, возвращает только агрегаты и всегда отправляет `Cache-Control: no-store`. Счётчик не используется для рекламы или межсайтового отслеживания.

## Эксплуатация

- Таблица: `common_dailyvisitstat`.
- Admin: «Посещения по дням», только чтение.
- Изменение определения посещения требует новой версии salt cookie и обновления этого документа.
- Перед миграциями production обязательна штатная резервная копия БД.
- Smoke-check не следует выполнять browser user-agent без необходимости: такой запрос корректно добавит одно реальное тестовое посещение. Для проверки исключения используйте `User-Agent: Blackbox monitoring`.
