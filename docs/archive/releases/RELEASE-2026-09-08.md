# Релиз Anicast: 08.09.2026

## Состав

Брендбук v0.1 применён к цветам, темам, шрифту и растровым ассетам. Светлая,
тёмная и системная темы доступны в шапке; выбор сохраняется и применяется до
первого отображения. У карточек каталога убрана дополнительная панель; цвета
мелких ссылок и клавиатурный фокус адаптированы к светлому фону. Версионные URL
маскота предотвращают сохранение старого знака в длительном кеше браузера.

Первый этап архитектурного перехода: независимые workers уведомлений и bulk-задач,
лимиты ресурсов frontend, запуск от node, постоянный image cache, исправленные
production project names и более строгие проверки релиза. Django signing key
заменён новым случайным значением; старые сессии/ссылки могут потребовать обновления.

Документация получила индекс, актуальный статус, архив истории, аудит, ADR,
`AGENTS.md` и проектные skills `anicast-ui` / `anicast-ops`.

## Ресурсы

Сборка выполнялась на MainServer, не на слабом VPS: `--resource memory=1g`,
`--resource cpu-quota=75000`, Node build heap 768 MiB, один build-time page worker.
На VPS frontend ограничен 512 MiB, runtime heap 320 MiB. Финальный замер через 45 минут после
выкладки: frontend 80.4 MiB, host available 509 MiB, restart count 0, OOM false.
Это наблюдение при обычном просмотре, не нагрузочный тест и не оценка ёмкости.

## Выкладка и восстановление

MainServer: `/home/lama_admin/anicast`, Compose project `mainserver`.
VPS: `/opt/anicast`, Compose project `vps`. Использованы скрипты deploy с
`ANICAST_LOCAL_IMAGES=1` и точными локальными image IDs после `docker save/load`.
Registry publication не выполнялась.

Финальный frontend image ID:
`sha256:dca947c614820dc8d87c4d6bec2604e74da05fa80edcb969fa2d58b6925b08a8`.

Состояние релиза:

- MainServer: `backups/releases/mainserver/{current,previous}.env`.
- VPS: `/var/lib/anicast/releases/vps/{current,previous}.env`.
- Исходный образ VPS до всех изменений темы дополнительно записан в
  `/var/lib/anicast/releases/vps/before-20260908.env`.
- Предрелизный снимок MainServer: `backups/predeploy-20260908/` — пользовательский
  diff, Compose-файлы, image IDs, приватная резервная копия env и дамп БД.
- Дамп проверен через `pg_restore --list`; восстановление offsite-копии в этой
  сессии не выполнялось.
- Исходный Compose VPS сохранён как `infra/vps/compose.pre-20260908.yml`.

Обычный rollback меняет образ и проверяет здоровье. Для отката разделения workers
нужно также восстановить сохранённый Compose-файл с исходным набором очередей.
Не очищать Redis queues и не восстанавливать production DB автоматически.
Резервный старый signing key не возвращать ради обычного image rollback.
