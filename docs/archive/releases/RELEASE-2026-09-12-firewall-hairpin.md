# Релиз 12.09.2026: firewall hairpin для проб site-availability

Инцидент 01:47–02:07 MSK: MainServer штатно выключился (poweroff, причина вне
журналов — sudo/UPS/thermal следов нет) и перезагрузился за минуту. Все 8
контейнеров `mainserver` и туннель AWG поднялись к 01:49. Внешние пользователи
не пострадали: Caddy на VPS отвечал 200 на протяжении всего окна.

Алерты: SiteDown (оба инстанса, снаружи сайт был жив), High5xxRate (~3 шт. 502
пока Caddy ждал backend, сам снялся в 02:07), SiteSlowWarning (следствие
таймаутов проб), PosterRefreshErrors (135/6ч — ~137 ошибок скучкованы в
01:17–01:47 при деградации сети; после — нули, отдельной поломки нет).

## Причина

Весь исходящий трафик MainServer идёт через туннель (`default dev awg0`,
таблица 51820). Пробы blackbox (`site-availability`, живут на MainServer)
упирались в `inet anicast_edge` на VPS: с awg0/10.78.0.2 были разрешены только
TCP 22/8443/9100. Доказано пакетами: SYN 10.78.0.2→VPS:443 доходят по awg0,
SYN-ACK не возвращается. Прямой путь снаружи (eth0) при этом отдавал 200.

## Изменение

- `infra/vps/firewall.nft`: awg0/10.78.0.2 разрешены TCP 80/443 — тот же набор
  публичных веб-портов, один доверенный пир; применено на VPS атомарной
  транзакцией (`anicast-firewall-apply`, сначала `nft --check`) с watchdog
  на откат 180с по runbook ADR 003 (не сработал, снят после проверки).
- `docs/architecture/003-vps-firewall.md`: поправка от 12.09.2026.

Откат: `/etc/anicast/firewall.nft.prev-20260911` и `/root/ruleset.backup-20260911`
на VPS, та же атомарная загрузка.

## Проверки (12.09.2026, MSK)

- Свежие curl с MainServer тем же путём, что пробы: `/` 200 за 0.77с,
  `/api/v1/titles/?page_size=1` 200 за 0.51с (было — таймауты 25с).
- `probe_success{job="site-availability"}` = 1 по обеим целям; SiteDown снялся.
- `verify-vps-firewall.sh` на VPS: exit 0; свежий fetch публичного origin из
  `vps-frontend-1` — 200.
- SiteSlowWarning и PosterRefreshErrors на момент записи ещё активны окнами
  (10м/6ч) — гаснут сами; новых ошибок постеров нет.
