# ADR 001: постепенное повышение устойчивости

Дата: 08.09.2026. Статус: принято, первый этап реализован.
Следующие этапы уточнены в [индексе ADR](README.md).

## Контекст

Сервис — модульный Django backend и Next frontend на двух небольших машинах.
Есть мониторинг и бэкапы, но единый worker смешивает интерактивные и длительные
задачи, процесс релиза расходится с production project names, frontend не ограничен
по памяти. Полная смена фреймворков эти причины отказов не устраняет.

## Решение

Сохранить Django/DRF и Next.js как поддерживаемые границы приложения. Начать
переход с изоляции фоновых задач и воспроизводимой эксплуатации:

1. `celery-worker`: default, notifications; `celery-bulk`: providers, posters,
   maintenance, analytics. Обе очереди обслуживаются независимо, concurrency 1.
   Маршрутизация задач и существующие Redis queues сохраняются; сообщения не очищаются.
2. Ограничить frontend memory/heap, запускать без root, сохранять image cache.
3. Применять темы через самостоятельный слой semantic tokens; CSS Modules и
   существующие API-контракты сохраняются.
4. Использовать реальные Compose names, обязательный исходный release manifest
   и immutable image identifiers. Миграции должны оставаться expand/contract.

## Следующие этапы и критерии

- Выделить cache Redis после измерения used_memory и проверки поведения при
  недоступности cache; критерий: cache fill/outage не блокирует enqueue.
- Перенести сборки на CI/отдельный builder, публиковать registry digests и проверить
  rollback на обоих хостах. Критерий: релиз воспроизводим без npm build в production.
- Рассмотреть размещение API/БД вне домашнего узла после определения RPO/RTO и
  проверки восстановления на отдельном хосте. Критерий: восстановленный каталог,
  пользователи и история согласованы; API/плеер smoke проходит до переключения DNS.

## Цена решения

Второй worker имеет дополнительную фиксированную память. Concurrency 1 ограничивает
скорость bulk-обработки, зато делает нагрузку предсказуемой. Постоянный image cache
требует контроля диска. Один VPS/MainServer остаются точками отказа; этот ADR
не заявляет high availability. Изменение цвета не меняет сами постеры или данные.

## Откат

Темы и frontend откатываются образом. Для возврата к одному worker сначала
восстановить прежний compose.yml с полной строкой очередей, затем пересоздать
worker; bulk завершить корректно, очередь не purge. Обычный image rollback
не восстанавливает конфигурацию Compose автоматически — её копия входит в
предрелизный снимок, описанный в отчёте релиза.
