# Карточка тайтла, метаданные и плеер

## Названия и поиск

`TitleSerializer.localized_names` отдаёт доступные официальные варианты в стабильном формате:

```json
{"ru": "Большой куш", "en": "One Piece", "ja": "ONE PIECE"}
```

Пустой язык не включается. Одинаковые официальные написания не объединяются: интерфейс сохраняет языковую подпись. Поле `name` остаётся локализованным согласно языку запроса для обратной совместимости. Каталог и глобальный поиск ищут по `Title.name`, `Title.original_name` и всем `TitleTranslation.name`.

## Авторы и персонажи

Основные авторы (режиссёр, сценарист, продюсер) показываются в обзоре тайтла; полный список остаётся во вкладке «Персонажи и авторы». Источник авторов — `material_data` Kodik, синхронизация выполняется существующей задачей `sync_kodik_library`.

Причиной неполного состава было историческое ограничение импорта `--characters=8`. `sync_title_characters` получает весь `characterRoles` одним серверным GraphQL-запросом к catalog provider, создаёт недостающие RU/EN-переводы и идемпотентно связывает роли с тайтлом. Тяжёлые карточки выдаются по 60 персонажей через `characters_page`; общее число находится в `characters_count`. Внешние портреты остаются в приватных origin-полях и публично выдаются только после локального зеркалирования.

Ручной запуск:

```bash
python manage.py sync_title_characters 21-one-piece --apply
python manage.py sync_title_characters --all --apply
```

Celery Beat запускает `catalog.tasks.sync_character_library` каждый час порциями по 5 тайтлов.

### Локальные портреты

`Character.image_origin_url` и `Creator.image_origin_url` — приватные server-side поля. Публичные сериализаторы принимают только AniCast media URL; origin не появляется в JSON, RSC, HTML, Open Graph или JSON-LD. Публичный запрос никогда не скачивает файл извне: при отсутствии локальной копии интерфейс сразу показывает брендовый fallback. `mirror_portraits` проверяет allowlisted HTTPS origin, размер и формат, сохраняет content-addressed файл в общий media volume и переключает `image_url` на immutable `/api/v1/media/posters/x-s-*`.

Полный prewarm: `python manage.py mirror_portraits --apply --workers 8`. Без `--apply` команда только считает кандидатов. Ошибка загрузки не возвращает hotlink — интерфейс показывает брендовый fallback.

## Названия и даты эпизодов

Первичный источник — Jikan/MAL. При недоступности Jikan используется `api.ani.zip`, который отдаёт TVDB-сопоставление, дату и RU/EN/JA-названия эпизода. Резервный источник:

- не перезаписывает редакторское название;
- не перезаписывает точное `air_at` от Kodik;
- заполняет только отсутствующие `air_date` и переводы;
- ограничен таймаутом 30 секунд и размером ответа 20 МБ.

Очередь выбирает эпизоды без названия **или** без даты, поэтому ранее пропущенные записи постепенно попадают в расписание после появления подтверждённых дат.

### Известный долг нумерации

Номер эпизода внутри карточки должен быть локальным номером этой работы. В текущем каталоге остаются исторические записи, где локальная нумерация источника смешана с абсолютной нумерацией метаданных. Из-за этого у части продолжений появились metadata-only эпизоды без плеера, а у двух фильмов — служебные строки вида `Part N of M`.

Это отдельная задача нормализации данных, а не условие общего UI-шаблона. Интерфейс не скрывает и не удаляет такие записи автоматически: среди эпизодов без источника могут быть настоящие будущие серии или редакторские материалы. Исправление требует dry-run аудита, подтверждённого сопоставления локальных номеров и отдельной управляемой миграции данных.

## Единый публичный маршрут

У каждого тайтла один публичный HTML URL: `/titles/<slug>`. Выбранная серия и вариант просмотра являются состоянием этой страницы и передаются как `/titles/<slug>?episode=N&voice=KEY#watch`. Query-параметры можно сохранять и отправлять другому человеку, но canonical всегда указывает на чистый `/titles/<slug>`; fragment `#watch` только прокручивает браузер к плееру.

Legacy HTML-маршрут `/titles/<slug>/episodes/<number>` удалён и отвечает 404 без redirect. Серверный endpoint `/api/v1/titles/<slug>/episodes/<number>/` остаётся: это внутренний JSON-контракт для загрузки метаданных и разрешённых источников выбранного эпизода, а не индексируемая страница.

### Номера каталога и номера с плеером

`GET /api/v1/titles/<slug>/watch-navigation/` разделяет две независимые сущности:

- `catalog_episode_numbers` — точный отсортированный список существующих строк `Episode`, включая будущие и metadata-only записи; API сохраняет реальные разрывы и не достраивает диапазон `1..episodes_count`;
- `playable_episode_numbers` — объединение серий, у которых сейчас есть хотя бы один разрешённый и доступный источник;
- `episode_numbers` — временный compatibility alias для `playable_episode_numbers`; новый frontend не должен использовать его как каталог серий;
- `source_groups[].episode_numbers` — покрытие конкретной озвучки, субтитров или оригинала.

Такое разделение позволяет показать честное состояние выбранной metadata-only серии, но не превращать её в доступную кнопку плеера. Ошибка загрузки навигации также не является основанием синтезировать номера из общего количества.

## Макет просмотра

AniCast владеет выбором серии и варианта озвучки/субтитров. Kodik остаётся поставщиком видео, но не создаёт второй конкурирующий уровень навигации внутри iframe. На desktop справа от плеера находится единственный контроллер просмотра: фиксированный выбор варианта, стрелки, поиск и прокручиваемый список серий. Нижний дублирующий контроллер скрыт. Нажатие на вариант временно заменяет список серий плоским списком озвучек в той же панели — отдельного модального окна нет.

На узком экране стрелки и текущая серия остаются под плеером, варианты озвучки раскрываются там же в потоке страницы, а длинный список серий открывается мобильной bottom-sheet панелью. Содержимое bottom sheet монтируется только после открытия. Календарной сетки и отдельного маршрута просмотра нет.

Вкладка «Эпизоды» содержит одну семантическую ссылку на всю строку: `/titles/<slug>?episode=N#watch`. Отдельной кнопки открытия и отдельной страницы в пользовательском потоке нет. Список запрашивает `episode_sources=0`, поскольку playback-источники нужны только после выбора серии; это сохраняет названия/описания/даты и убирает лишний source payload.

Длинные сериалы делятся на диапазоны максимум по 100 доступных номеров. На desktop рендерится выбранный диапазон, поиск остаётся доступен рядом со списком; на mobile используется тот же контракт, но длинный список загружается в DOM лениво при открытии панели.

### Одиночный просмотр

Фильм всегда рендерится как одна единица просмотра, даже если исторические метаданные ошибочно содержат дополнительные provider-less части. OVA и special используют тот же compact-режим, когда в каталоге не больше одного эпизода. В этом режиме скрыты счётчик, вкладка эпизодов, стрелки, поиск и диапазоны, но выбор озвучки/субтитров остаётся доступным. Многосерийные OVA и special продолжают использовать обычный episodic-режим.

### Честные состояния

- `no-player`: навигация загружена, но у тайтла или выбранной серии нет разрешённого источника; интерфейс сообщает об этом и не подменяет серию молча;
- `degraded`: матрица навигации временно не загрузилась, но карточка и доступный источник выбранного эпизода могут работать; показывается предупреждение и повторная загрузка, номера не изобретаются;
- `invalid`: `episode` или `voice` не существует либо не подходит одиночному режиму; UI открывает безопасный доступный вариант, объясняет коррекцию и нормализует адрес через History API без redirect и второй индексируемой страницы.

Варианты сохраняют серверный порядок и не пересортировываются после выбора; тип источника показывается внутри строки. Каждый вариант показывает реальное покрытие (`1–130`, `1–1122, кроме 269, 278`), а не долю запусков. Без явного `?voice=` frontend выбирает первый вариант серверного рейтинга, у которого есть источник текущей серии. Явно выбранный вариант сохраняется даже при недоступности, а интерфейс показывает предупреждение вместо молчаливого переключения.

### Стабильная идентификация варианта

Для источников Kodik API отдаёт `provider_variant_id` — строковый `translation_id` провайдера, одинаковый у всех серий одной озвучки или набора субтитров. Публичный `selection_key` остаётся непрозрачным, но строится из provider, типа источника и этого стабильного идентификатора, а не из отображаемого названия. Переименование студии в Kodik поэтому не ломает сохранённый выбор и новые `?voice=` URL.

Группа в `/watch-navigation/` дополнительно содержит `legacy_key`, рассчитанный по прежней схеме provider + тип + текущее название. Frontend принимает как новый `key`, так и `legacy_key`; при распознавании старой ссылки заменяет query-параметр на стабильный `key`. `SourceSerializer` отдаёт `provider_variant_id` и тот же `selection_key`, чтобы выбранная группа однозначно сопоставлялась с источником текущего эпизода.

Для источников без подтверждённого стабильного идентификатора `provider_variant_id` равен `null`, а `selection_key` сохраняет прежнюю схему. Название не используется как Kodik identity и не раскрывает внутренний content id провайдера.

### Параметры iframe Kodik

`sync_kodik` сохраняет текущую episode-specific ссылку источника с `hide_selectors=true`. Существующие безопасные query-параметры сохраняются, ранее переданный `hide_selectors` заменяется, а `only_episode` удаляется. Режим `only_episode` не применяется: AniCast переключает конкретные серии своими per-source ссылками, не отключая совместимый serial runtime Kodik.

Параметр хранится непосредственно в URL источника; `Provider.playback_config` остаётся пустым. Это сохраняет совместимость с предыдущей версией iframe adapter и позволяет откатить backend без остановки playback. После выкладки требуется целевой либо полный `sync_kodik --apply`, чтобы обновить уже существующие Source.

Счётчик увеличивается только после успешной проверки короткоживущего playback-токена и перенаправления к провайдеру. Абсолютное число запусков наружу не отдаётся — API возвращает только `popularity_percent` для порядка вариантов; интерфейс не выдаёт эту метрику за покрытие озвучки. Навигация кэшируется на 60 секунд, поэтому новый порядок может появиться с небольшой задержкой. Пользовательские блоки «Доступно серий» и «Все источники и диагностика» из страницы просмотра удалены.

URL источника никогда не входит в навигационный payload: iframe по-прежнему получает короткоживущую подписанную ссылку через playback resolver.

## Настройки сайта в Kodik

В кабинете Kodik сайт настроен для `*.anicast.online`, включая поддомены. Данные доступа и внутренний идентификатор сайта в репозитории, документации и логах не сохраняются.

Глобальная доступность встроенных селекторов, автосохранение и автоматическое переключение в кабинете оставлены без изменений ради безопасного rollback. В актуальном интерфейсе внутренние селекторы скрываются только параметром конкретного Source URL. Брендовые цвета AniCast применены на стороне Kodik, поэтому резервный интерфейс плеера не выбивается из визуальной системы сайта.

## Проверка после выкладки

1. `/api/v1/titles/21-one-piece/` содержит `localized_names`, `characters_count`, `credits`, но ни одного внешнего artwork URL.
2. Поиск RU/EN/JP-вариантов возвращает один и тот же slug.
3. `/titles/21-one-piece?tab=characters&characters_page=2` открывает следующую страницу состава.
4. `/watch-navigation/` отдаёт раздельные `catalog_episode_numbers` и `playable_episode_numbers`; старый `episode_numbers` совпадает со вторым как compatibility alias.
5. `/watch-navigation/` отдаёт одинаковый `key` для Kodik-источников с одним `provider_variant_id`, даже если отображаемое название изменилось, и содержит рабочий `legacy_key`.
6. Playback resolver перенаправляет на episode-specific URL с `hide_selectors=true`, без `only_episode` и без раскрытия URL в навигационном payload.
7. `/titles/21-one-piece?episode=1` переключает серии и озвучки на карточке тайтла; на поздней серии без `voice` выбирается первый доступный ranked-вариант; `/titles/21-one-piece/watch` и `/titles/21-one-piece/episodes/1` отвечают 404 без redirect.
8. Количество `Episode(air_date IS NULL)` уменьшается после фоновых проходов; точные `air_at` не меняются.
9. `/titles/21-one-piece?tab=episodes` не содержит текста «Открыть эпизод»; Enter на строке открывает встроенный плеер.
10. `mirror_portraits --title 21-one-piece` после prewarm показывает 0 кандидатов, а API/HTML содержат только `/api/v1/media/*`.
