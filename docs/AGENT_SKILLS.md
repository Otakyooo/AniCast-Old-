# Проектные skills Anicast

Единая точка входа — [AGENTS.md](../AGENTS.md). Skills версионируются в
`.agents/skills/`; личные установки и настройки других проектов не меняются.

| Skill | Когда читать | Подробные источники |
| --- | --- | --- |
| [anicast-ui](../.agents/skills/anicast-ui/SKILL.md) | Страницы, компоненты, темы, формы, UI review | Бренд и правила интерфейса |
| [anicast-backend](../.agents/skills/anicast-backend/SKILL.md) | Django/DRF, модели, миграции, API, Celery, review границ | Application runbook, архитектура, профильные документы |
| [anicast-ops](../.agents/skills/anicast-ops/SKILL.md) | Релиз, runtime, ресурсы, backup/recovery, firewall | Разделы эксплуатации и история проверок |

`CLAUDE.md` и правило Cursor направляют в те же источники. Полные копии skills
для разных редакторов не поддерживаются. Полезные правила прежних 44 файлов
`.claude/skills/*.md` сведены в три предметных skill и профильные документы;
общие советы, дубли и обязательное согласование каждого плана удалены.
Прежние файлы доступны в git до этой уборки. Старые Kilo-планы помещены в архив.

Skill выбирается по задаче; загружать все три для каждой правки не требуется.
Новые правила добавляются при конкретном отличии Anicast от обычного проекта,
а не ради универсального процесса. Команды проверок живут в deployment runbook;
skills не вводят другую конфигурацию линтеров или второй список обязательных тестов.
Для документации проверяются ссылки/пути, структура skills и diff; сборка приложений
нужна при изменении кода/зависимостей, а не при перемещении Markdown.

### Правило обновления

Новые внешние инструкции сначала проверяются на лицензию, актуальность и конфликт
с `docs/BRAND_UI_TECH_SPEC.md`. В проект переносится только правило, которое меняет
реальное инженерное решение AniCast; общие призывы писать «качественный код» и
зависимости отсутствующего стека не добавляются.
