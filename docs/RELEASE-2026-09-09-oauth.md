# Резервные копии: собственный Google OAuth-клиент

Завершено 09.09.2026 по Москве, 08.09 23:45–23:48 UTC. Владелец самостоятельно
прошёл защитный экран Google и согласился на доступ Anicast Backups к Drive.
MainServer использует собственный Desktop client **Anicast rclone recovery**.
Google app имеет Production status, но не публичную верификацию Google.

## Переключение и проверка

1. Токены и секрет клиента прочитаны только из приватных файлов. Новый rclone
   config подготовлен отдельно; сравнение подтвердило сохранение crypt keys,
   root folder и всех настроек, кроме client ID/secret/token.
2. Искусственно истёкший access token обновился через Google на Windows, затем
   независимо на MainServer. Проверено появление нового access token с будущим
   expiry и наличие refresh token; однократный успешный запрос не выдавался за
   проверку продления доступа.
3. Уникальный 128-байтовый объект записан через gdcrypt, прочитан с полным
   побайтовым совпадением и удалён. Существующие резервные копии этим тестом
   не изменялись; сообщения пользователям не отправлялись.
4. На MainServer взяты существующие locks DB/media/recovery jobs; config заменён
   атомарно с mode 600. Прежний файл сохранён приватно под именем
   `rclone.conf.pre-oauth-20260908T234538Z`. До изменения production новый config
   прошёл проверку доступа непосредственно с сервера.
5. `BACKUP_NOTIFY=0 scripts/backup-db.sh` создал и выгрузил новую копию. Она
   скачана с Drive непосредственно на Windows и проверена по SHA-256.
6. Пересозданы и выгружены оба age-комплекта. Они тоже скачаны непосредственно
   из Drive и расшифрованы в памяти на Windows: все 21 файла MainServer и 11 VPS
   совпали с manifest hashes. MainServer kit содержит собственный OAuth-клиент,
   refresh token и прежние crypt keys. Ключ age на серверы не передавался.

## Проверенные артефакты

- DB: `anicast-20260908T234538Z.dump`, 3 541 281 байт.
- SHA-256: `67e84b48d4bf3736f041c9f0bc96a099dc55167b49dfa68d34a2b87f66696edb`.
- Kits: `mainserver-20260908T234633Z.age`, `vps-20260908T234633Z.age`.
- Локальные kits: `C:\Users\Nasa\.ssh\anicast-recovery`, закрытый ACL.

После проверки удалены временные открытые rclone configs, OAuth token logs и
скачанный проверочный дамп. Зашифрованные kits и приватная серверная конфигурация
для отката сохранены. Prometheus уже содержит новые offsite timestamps DB и kits.

Freshness exporter обновлён; backend scrape и три Redis role metrics проверены.
Перезапуск приложения, изменение образов или миграция БД не требовались.
Полный DR не повторялся: менялся доступ к хранилищу, а не формат данных/приложение.
Последний полный DR описан в [hardening release](RELEASE-2026-09-09-hardening.md).
Проверки предыдущего кода, включая capacity report, и публикация образов прошли
в [CI 34291367680](https://github.com/Otakyooo/AniCast/actions/runs/34291367680).

Сохранённая конфигурация для отката содержит прежние credentials; удалять её
после периода наблюдения по эксплуатационному регламенту. Резервные копии
остаются зависимы от доступности аккаунта Google и офлайн-ключа владельца.
Постоянный перенос API/БД вне дома требует внешнего хоста; увеличение домашней
RAM само по себе эту зависимость не устраняет.
