# Ресурсы: суточная история вместо одиночного снимка

Дата: 09.09.2026 по Москве. Владелец планирует увеличить MainServer до 4 ГБ RAM
позже. Текущие лимиты и concurrency сохранены; увеличение CPU не подтверждено.

Добавлен `scripts/capacity-report.py`: чтение существующего Prometheus по loopback,
без нового сервиса, фонового расписания или уведомлений. Отчёт содержит RAM,
CPU/I/O wait, активный swap и доступность exporter для обоих хостов.
Окно 1–72 часа, шаг 5 минут, CPU/swap усреднены за 5 минут. Отсутствующие или
нечисловые данные не превращаются в нулевую нагрузку; видна полнота каждого ряда.
Исправлен устаревший раздел OPERATIONS про два Redis и опасный возврат к старому
control URL при откате: действующая схема использует три отдельных роли.

## Реальные измерения

Окно суток: 07.09 23:34 — 08.09 23:34 UTC. Окно часа: 08.09 22:34–23:34 UTC.
Для каждого сигнала получены 289/289 и 13/13 точек соответственно; `scrape_up=1`
во всех выбранных точках. Это дискретные наблюдения exporter, не SLA сайта.

| Показатель | MainServer | VPS |
| --- | ---: | ---: |
| Всего RAM | 2582 MiB | 961 MiB |
| Минимум доступной RAM за сутки | 459 MiB | 168 MiB |
| Минимум доступной RAM за последний час | 1056 MiB | 438 MiB |
| Доступно в конце часового окна | 1399 MiB | 497 MiB |
| CPU busy: p95 за сутки | 34.1% | 22.3% |
| CPU busy: максимум за сутки | 96.9% | 51.3% |
| CPU busy: максимум за последний час | 26.7% | 51.3% |
| Swap-out: максимум за сутки, страниц/с | 4847.2 | 14.1 |
| Swap-out: последнее значение, страниц/с | 0 | 0 |

Суточное окно включает работы по релизу и восстановлению. Причина каждого пика
не установлена этим отчётом. На MainServer были периоды активного swap, поэтому
короткий спокойный замер нельзя распространять на весь день. Последний час
показывает больший запас RAM, но тоже включает обслуживание. 4 ГБ дадут полезный
запас; текущие данные не требуют немедленного изменения лимитов. CPU busy включает
I/O wait: он выведен отдельным сигналом. Число поддерживаемых одновременных
посетителей нагрузочным тестом не определялось.

## Проверки и выкладка

Шесть unit tests пройдены: пустая история, NaN/Inf, percentile/последняя точка,
отсутствующий хост, сохранение отказа exporter и отказ при дублировании рядов.
`scripts/validate.sh` теперь включает эти проверки; полный прогон на изолированном
снимке исходников прошёл Compose/Prometheus/Alertmanager и сценарии deploy/rollback.
Production данные и пользовательские удаления файлов не затрагивались.

Скрипт проверен на живом Prometheus с окнами 24h и 1h. Для установки достаточно
синхронизации репозитория MainServer; перезапуск приложения и новые образы не нужны.
На момент этого этапа OAuth consent и внешний хост ожидались. Затем OAuth
[завершён и проверен](RELEASE-2026-09-09-oauth.md); внешний хост не предоставлен.
