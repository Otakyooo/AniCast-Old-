# Anicast: текущее состояние

Проверено 09.09.2026. Это текущая сводка; последовательность релизов и прежние
планы находятся в [архиве](archive/README.md).

## Что работает

- Next.js 16.3.4 / React 19.2.8 / TypeScript: каталог, плеер разрешённых источников,
  библиотека, история, коллекции, публичные opt-in профили, поиск, уведомления.
- Django 5.2 / DRF / PostgreSQL 17 на MainServer; публичный Next/Caddy на VPS,
  связь через AWG. Backend — модульный монолит.
- Три Redis: broker/results, обязательная координация и необязательный cache.
  Два Celery workers с concurrency 1; отдельные очереди уведомлений и bulk.
- Только светлая и тёмная темы, общие для сайта и админки; по умолчанию тёмная.
  Системная тема удалена, белая подложка логотипа исправлена. Админка использует
  брендовые static CSS/JS под действующей CSP. Manrope, SVG бренд и metadata. HTML получает
  уникальный nonce CSP и private/no-store; image cache переживает релиз.
- CI проверяет backend/frontend/infrastructure и публикует GHCR images по digest.
  Есть immutable release env, health gates, image rollback, firewall и мониторинг.
- На VPS развёрнут Next 16.3.4 / sharp 0.35.4; js-yaml обновлён до 4.3.2.
  npm audit: 0 уязвимостей; high/critical блокируют CI. Native image runtime и
  браузерная проверка прошли. CI включает 73 unit tests и 9 Chromium E2E проверок
  общего каркаса на трёх размерах экрана. [Релиз](archive/releases/RELEASE-2026-09-09-next16.md).
- Внешние зашифрованные DB/media backups и recovery kits. Собственный Google
  OAuth активен; refresh/read/write и SHA-256 новой копии проверены вне MainServer.
  Последние kits: 20260909T113324Z, все 21/11 файлов проверены;
  копии из Drive и предрелизный DB dump независимо сверены по SHA-256.
- Исправлено растягивание страницы тайтла лентой похожих тайтлов и вложенными
  сетками; production проверен на 1280/820/390 px в обеих темах.
- Полная изолированная репетиция restore/login/reset/notification sink/player
  и private proxy switch/rollback прошла за 142.16s без скачивания файлов/образов.

## Ресурсы и ограничения

MainServer: 1 CPU, ОС уже видит 3606 MiB RAM после увеличения памяти. Лимиты
и concurrency сохранены. VPS: 1 CPU, 961 MiB RAM; сборки выполняются вне серверов.
В измеренном часу перед релизом MainServer имел минимум 2056 MiB доступной RAM,
CPU (5m) не превышал 15.84%. На VPS минимум был 487 MiB; после холодной обработки
постера — 323 MiB. Это запас при наблюдаемой нагрузке, а не нагрузочный предел сайта.

MainServer, домашний канал/питание и единственный VPS остаются точками отказа.
Нет подтверждённого HA или постоянного переноса API/БД; внешний хост не предоставлен.
RPO-цели 6h DB / 24h media зависят от успеха offsite, RTO-цель 2h — от наличия
хоста и ключей. Полный mobile/screen-reader E2E и нагрузочная ёмкость не доказаны.

## Ближайшие приоритеты

1. Разделить запуск API и остановку bulk в deploy: длительное завершение worker
   задержало запуск уже пересозданного API. После ручного запуска сервисы здоровы.
2. Добавить E2E входа/плеера и нагрузочный профиль; отдельно переработать 18
   предупреждений React effects в старых компонентах под сценарными тестами.
3. Перенести data tier на предоставленный внешний хост; RAM дома этого не заменяет.
