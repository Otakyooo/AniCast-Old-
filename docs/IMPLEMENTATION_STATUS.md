# Anicast: текущее состояние

Проверено 12.09.2026. Это текущая сводка; последовательность релизов и прежние
планы находятся в [архиве](archive/README.md).

## Что работает

- Next.js 16.3.4 / React 19.2.8 / TypeScript: каталог, плеер разрешённых источников,
  библиотека, история, коллекции, публичные opt-in профили, поиск, уведомления.
- Django 5.2 / DRF / PostgreSQL 17 на MainServer; публичный Next/Caddy на VPS,
  связь через AWG. Backend — модульный монолит.
- Три Redis: broker/results, обязательная координация и необязательный cache.
  Два Celery workers с concurrency 1; отдельные очереди уведомлений и bulk.
- Только светлая и тёмная темы, общие для сайта и админки; по умолчанию тёмная.
  Системная тема удалена, белая подложка логотипа исправлена. Админка использует
  брендовые static CSS/JS под действующей CSP. Manrope, SVG бренд и metadata. HTML получает
  уникальный nonce CSP и private/no-store; image cache переживает релиз.
- UX-редизайн 09.09.2026: поверхности разведены по светлоте (фон → карточка →
  панель/hover), контейнеры разделаются фоном и отступами, а не рамками; янтарь
  зарезервирован для CTA и фокуса, ссылки/подписи — спокойный крем (dark) /
  ягодный (light); минимальный текст 13 px (12 px только для микро-бейджей и
  мобильной нижней навигации); контейнер 1440 px; полки — с осознанным peek
  следующей карточки и стрелками по hover.
- Главная: компактный hero «Продолжить просмотр» с текстовым прогрессом
  («Серия 3 из 1180 · просмотрено 14:52») и вторичной кнопкой библиотеки; полки
  «Недавно вышли» (`/api/v1/episodes/recent/`) и «Сейчас выходит» с номером
  последней серии и датой следующей (`/api/v1/titles/airing/`); «Популярное»
  переименовано в «Чаще добавают» по фактической метрике; франшизы опущены
  ниже рекомендаций; поиск в шапке шире и выше (44 px).
- «Недавно вышли» получает окно 30 дней и само решает, что показать: полная
  неделя идёт в полку, редкая неделя дополняется релизами постарше с честной
  подписью «за месяц», а меньше четырёх серий переключают блок в компактные
  строки без зарезервированной высоты постеров вместо пустой полки.
- Страница тайтла: один русский заголовок с «Другими названиями» в disclosure;
  одна строка метаданных «год · статус · N серий × M мин»; рейтинг «★ 4.8 ·
  N оценок» у названия; синопсис 4 строки + «Подробнее»; единая система списков
  («Статус: Не в списке ▾» одним контролом, «Любимое» внутри), отдельные кнопки
  «В библиотеку»/«Избранное» удалены; у завершённых тайтлов нет кнопки
  уведомлений; вкладки Обзор/Серии основные, Персонажи/Сообщество/Заметки —
  вторичные в той же группе, а не у противоположного края экрана;
  при `?episode=` hero компактен, люди-блоки скрыты;
  панель серий 380 px с сильным выделением текущей; prev/next с подписями под
  плеером; автопереход «Следующая серия через 10…» с отменой по событию ended;
  озвучка/субтитры — подписанные селекторы; «⚠ Проблема с видео» возле плеера;
  блок «Порядок просмотра» франшизы с нумерацией шагов.
- Счётчики серий не спорят между собой: панель и диалог выбора серии пишут
  «60 серий всего · 30 доступны в выбранной озвучке», кнопка под плеером —
  «Доступно 30 из 60»; равные числа оставляют прежнюю короткую подпись.
- Списки серий длиннее 40 доступных получают селектор диапазонов (шаг 25/50/100
  и далее по объёму), поэтому длинный сериал листается блоками, а не только
  поиском по номеру. Арок в данных нет — диапазоны нумерации это и есть
  честная реализация.
- Локализованные поля откатываются на непустое значение: строка перевода с одним
  именем больше не прячет импортированное описание (у всех 100 тайтлов была
  пустая `ru`-строка синопсиса, из-за чего описание не показывалось нигде,
  включая meta description и JSON-LD).
- Профиль: баннер сокращён втрое, аватар компактнее; «Продолжить просмотр»
  сразу после шапки; статистика одной строкой; график активности скрыт до
  8 просмотренных серий и сокращён вдвое; «Любимые жанры» (chips с счётчиками)
  не показываются до 10 тайтлов в библиотеке; нижние карточки-дубли разделов
  удалены.
- Рекомендации исключают любой просмотренный прогресс (не только полностью
  просмотренные) и оставляют одного представителя франшизы, чтобы её части
  не шли подряд в одном ряду.

## Ресурсы и ограничения

MainServer: 1 CPU, ОС уже видит 3606 MiB RAM после увеличения памяти. Лимиты
и concurrency сохранены. VPS: 1 CPU, 961 MiB RAM; сборки выполняются вне серверов.
Короткая проверка 36 публичных GET при параллельности 1/2/4 прошла без ошибок;
при 4 запросах p95/max составил 938ms. Это smoke без видео, cold image
processing и авторизованных записей, а не заявленная ёмкость: число
одновременных зрителей и сезонный пик неизвестны. Во время проверки доступная RAM была
не ниже 1974.8 MiB на MainServer и 433.7 MiB на VPS, без OOM/перезапусков.
Короткие CPU busy пики достигали 100%/77.8% с учётом фоновой работы и iowait.
Это запас при наблюдаемой небольшой нагрузке, а не максимальный онлайн сайта.

MainServer, домашний канал/питание и единственный VPS остаются точками отказа.
Нет подтверждённого HA или постоянного переноса API/БД; внешний хост не предоставлен.
RPO-цели 6h DB / 24h media зависят от успеха offsite, RTO-цель 2h — от наличия
хоста и ключей. Safari/Firefox/screen-reader E2E и нагрузочная ёмкость не доказаны
(Chromium E2E после фиксов — 72/72 локально, CI зелёный).

## Ближайшие приоритеты

1. Расширить проверки на Safari/Firefox, скринридер и длительную смешанную нагрузку.
2. Следующий UI-этап: ошибки/пагинация франшиз и сообщества, переход к коллекциям
   и редактор коллекций; затем остальные личные действия и карточки.
3. Держать data tier дома до появления бесплатного внешнего хоста; RAM дома
   переезд не заменяет. Платный переезд не планируется (zero-budget).
