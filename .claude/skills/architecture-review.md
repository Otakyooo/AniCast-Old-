# Architecture Review

Проверка границ модулей и зависимостей.

## Проверки

1. **Границы модулей**: каждый модуль (common, titles, users, library) имеет чёткую ответственность
2. **Зависимости**: нижние слои не импортируют верхние (DB → models → services → views → API)
3. **Общий код**: shared utilities в `common`, не дублируются по модулям
4. **API-контракты**: frontend не зависит от внутренней структуры backend, только от публичного API
5. **Infrastructure**: Docker/Compose не содержит бизнес-логики, только оркестрацию

## Вопросы для ревью

- Можно ли удалить/заменить модуль без переписывания соседей?
- Есть ли циклические зависимости между apps?
- Нарушает ли изменение принцип единой ответственности?
- Соответствует ли структура кода архитектуре из docs/?

## Антипаттерны

- Модуль «God object» — один файл/модуль делает всё
- Feature envy — код в одном модуле работает преимущественно с данными другого
- Прямой доступ к чужим моделям в обход service-слоя
- Смешение presentation и business logic в views
