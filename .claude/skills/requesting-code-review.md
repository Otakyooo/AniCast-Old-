# Requesting Code Review

Формирование понятного review handoff для другого разработчика или ревьюера.

## Шаблон запроса

1. **Что изменено**: список файлов/модулей с кратким описанием
2. **Зачем**: ссылка на задачу/требование из docs/
3. **Что проверить**: конкретные вопросы к ревьюеру (архитектура? безопасность? производительность?)
4. **Что НЕ менять**: границы скоупа, которые не подлежат обсуждению
5. **Тесты**: какие добавлены, какие сценарии покрывают
6. **Риски**: известные компромиссы или technical debt

## Правила

- Не просить ревью «всего» — конкретизировать область
- Указывать контекст: почему именно так, какие альтернативы отвергнуты
- Если есть deadline — указать явно
