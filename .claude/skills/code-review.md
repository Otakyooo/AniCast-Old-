# Code Review

Ревью изменений перед merge.

## Процесс

1. **Сбор контекста**: `git diff` или `git diff --cached` для определения набора изменений
2. **Классификация**: разделить изменения на категории (новая логика, рефакторинг, фикс, конфиг)
3. **Проверка по измерениям**:
   - Корректность: логика, edge cases, пустые состояния, race conditions
   - Безопасность: auth, permissions, input validation, secrets
   - Производительность: N+1, лишние запросы, объём данных
   - Читаемость: naming, структура, соответствие окружающему коду
   - Тесты: покрытие новых путей, регрессионные тесты
4. **Верификация**: каждое замечание проверять — не ложное ли это срабатывание
5. **Отчёт**: ранжировать по серьёзности (critical → major → minor → suggestion)

## Правила

- Не хвалить код, который просто корректен — это ожидаемо
- Замечание должно содержать: файл, строку, проблему, сценарий отказа
- Предлагать исправление только если оно очевидное; иначе — описать направление
- Проверять cross-module impact: изменение API → все consumers
- Сверяться с docs/ при ревью бизнес-логики
