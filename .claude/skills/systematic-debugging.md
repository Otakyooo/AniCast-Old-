# Systematic Debugging

Пошаговый поиск причин ошибок — от симптомов к root cause.

## Процесс

1. **Воспроизвести**: получить точное сообщение об ошибке, стек, HTTP-код, или описание неправильного поведения
2. **Зафиксировать симптомы**: что ожидается vs что происходит; при каких условиях
3. **Сузить область**:
   - Слой: frontend → API → service → DB → infra
   - Время: когда началось, что менялось последним
   - Данные: специфичные inputs или любые
4. **Гипотезы**: сформулировать 2–3 вероятные причины, начиная с самых простых
5. **Проверка**: по одной гипотезе за раз, с конкретным экспериментом для каждой
6. **Root cause**: найти первопричину, а не симптом
7. **Fix**: исправить причину; добавить тест, предотвращающий регрессию
8. **Verify**: подтвердить, что фикс решает проблему и не ломает смежное

## Антипаттерны

- Не патчить симптом без понимания причины
- Не менять несколько вещей одновременно — невозможно определить, что помогло
- Не считать проблему решённой, если она «сама прошла» — найти, что изменилось
- Не игнорировать «невозможные» ошибки — они указывают на неверное понимание системы
