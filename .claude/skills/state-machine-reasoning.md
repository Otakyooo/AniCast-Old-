# State Machine Reasoning

Моделирование допустимых состояний и переходов сложного пользовательского или backend-сценария.

## Процесс

1. Перечислить состояния, владельца state и допустимые переходы.
2. Для каждого перехода указать trigger, guard, side effects и failure result.
3. Проверить initial, terminal, повторный, просроченный и конкурентный переход.
4. Сопоставить модель с DB constraints, API status codes и UI states.
5. Написать тесты на happy path и запрещённые переходы.

## Антипаттерны

- Boolean flags вместо явно описанных взаимоисключающих состояний.
- Переход, который меняет state до завершения обязательного side effect.
