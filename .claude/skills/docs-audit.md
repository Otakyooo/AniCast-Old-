# Docs Audit

Сверка реализации, тестов и конфигурации с требованиями в `docs/`.

## Процесс

1. Определить, какие документы и разделы относятся к изменению.
2. Извлечь конкретные требования, ограничения, API-контракты и приоритеты.
3. Сопоставить каждое требование с кодом, тестом и фактическим поведением.
4. Проверить расхождения между документацией, текущей реализацией и задачей.
5. Зафиксировать статус: выполнено, частично, отложено, противоречиво или не проверено.

## Правила

- Не объявлять feature готовой только по наличию похожего кода.
- Ссылаться на конкретный документ и раздел, а не на расплывчатое «по docs».
- Если документ противоречит другому источнику, сначала применить `contradiction-detection`.
- Документацию не переписывать молча в рамках реализации: изменение требований должно быть отдельным решением.
