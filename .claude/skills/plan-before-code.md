# Plan Before Code

Обязательный порядок: анализ → план → точки проверки → реализация.

## Процесс

1. Прочитать релевантные docs, код и тесты.
2. Зафиксировать требования, ограничения, допущения и затронутые модули.
3. Предложить минимальный план с критическими файлами и альтернативами.
4. Определить проверки для каждого шага и критерий остановки.
5. Выполнять код только после согласования плана; изменения держать в заявленном scope.
6. После реализации запустить `implementation-review` и верификацию.

## Антипаттерны

- Начинать с редактирования первого найденного файла.
- План без проверки consumers, миграций или error paths.
- Считать успешную компиляцию доказательством бизнес-корректности.
