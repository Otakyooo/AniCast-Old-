# Test-Driven Development

TDD цикл: Red → Green → Refactor для backend и frontend.

## Процесс

1. **Red**: написать тест, который падает по правильной причине (функция ещё не реализована или поведение ещё не добавлено)
2. **Green**: написать минимальный код, чтобы тест прошёл
3. **Refactor**: улучшить код, сохраняя все тесты зелёными

## Backend (Django/DRF)

```python
# 1. Тест — backend/titles/tests.py
def test_title_list_returns_200(client):
    resp = client.get("/api/v1/titles/")
    assert resp.status_code == 200

# 2. Реализация — минимальная
# 3. pytest -x → green
# 4. Refactor
```

## Frontend (Next.js)

- Тестировать через React Testing Library или Playwright
- Каждый компонент: рендер → взаимодействие → ожидаемый результат
- API-интеграция: mock fetch, проверить обработку состояний

## Правила

- Тест пишется ДО кода, а не после
- Один тест = одно поведение, не «тест всего»
- Тест должен быть детерминированным: без sleep, без внешних сервисов без моков
- Если тест невозможно написать до кода — это сигнал, что архитектура не тестируема
