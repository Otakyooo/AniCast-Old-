# Failure Analysis

Поиск первопричины после неудачного теста, deploy или пользовательского сценария.

## Процесс

1. Сохранить точный симптом, stack trace, request, state и временную шкалу.
2. Воспроизвести отказ минимальным стабильным сценарием.
3. Разделить область по слоям: frontend → API → service → DB → infra.
4. Сформулировать 2–3 гипотезы и проверить каждую отдельным экспериментом.
5. Найти root cause, а не патчить симптом.
6. Исправить причину, добавить regression test и проверить соседние flows.

## Правила

- Не менять несколько независимых причин одновременно.
- Не считать исчезновение ошибки доказательством исправления.
- После инфраструктурного отказа проверить логи, healthchecks и конфигурацию.
