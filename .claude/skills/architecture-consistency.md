# Architecture Consistency

Проверка соответствия изменения установленным архитектурным правилам.

## Проверки

1. Сопоставить change с архитектурой из `docs/` и текущими границами модулей.
2. Проверить направление зависимостей: DB/models → services → views/API → frontend.
3. Убедиться, что бизнес-логика не попала в presentation или infrastructure.
4. Проверить публичные контракты и отсутствие циклических импортов.
5. Сравнить с существующими patterns; отклонение должно иметь decision log.

## Антипаттерны

- God module, прямой доступ к чужому persistence и скрытый shared state.
- Новый слой только ради обхода уже существующего публичного API.
