# Constraint Tracking

Явный список требований, ограничений и принятых решений.

## Процесс

1. Составить таблицу: ограничение, источник, проверка, статус.
2. Отметить технические ограничения backend, frontend, DB, infra и release-процесса.
3. При каждом изменении проверить, какие ограничения затронуты.
4. Обновлять статус только после конкретного evidence: теста, docs или команды.

## Правила

- Не превращать предположение в ограничение без источника.
- Невыполненное или неизвестное ограничение блокирует release, пока не принято решение.
- Сверяться с `docs/` и `docs/IMPLEMENTATION_STATUS.md`.
