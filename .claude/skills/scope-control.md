# Scope Control

Контроль границ задачи и защита от несвязанных улучшений.

## Процесс

1. Зафиксировать in-scope, out-of-scope и критерии готовности до изменения кода.
2. Для каждого обнаруженного улучшения спросить, нужно ли оно для текущего результата.
3. Отложенные идеи записать отдельно с причиной, не смешивая их с текущим diff.
4. Перед merge проверить каждый изменённый файл на связь с задачей.

## Правила

- Не расширять задачу из-за удобного места для рефакторинга.
- Bugfix, security fix и необходимая совместимость остаются в scope даже если не были заметны сначала.
- Непредвиденное изменение scope требует обновления плана и повторной проверки.
